ARCHITECTURE (src/):
- config.ts: loads env (MODE=mock|live, PORT=3000, TWITCH_CLIENT_ID, TWITCH_USER_TOKEN, TWITCH_BROADCASTER_ID, TWITCH_BOT_USER_ID, LIBRETRANSLATE_URL, LIBRETRANSLATE_API_KEY, OPENAI_ENABLED=false, OPENAI_API_KEY, NLLB_URL, hype + game tuning). Write .env.example (no secrets) and .gitignore (node_modules, .env, dist).
- twitch/types.ts: interfaces ChatSource (emits normalized ChatMessage {id, user, text, emotes[], ts}) and HelixClient {createMarker(desc), createClip(): {id, editUrl}, getClip(id), sendChatMessage(text)}.
- twitch/eventsub.ts: live ChatSource using EventSub WebSocket (wss://eventsub.wss.twitch.tv/ws), on session_welcome subscribe to channel.chat.message v1 via Helix POST /eventsub/subscriptions with the user token; handle keepalive, reconnect, revocation. Live code must compile but is not exercised now.
- twitch/helix.ts: live HelixClient using fetch: POST /streams/markers, POST /clips?broadcaster_id=..., poll GET /clips?id=... until available (with timeout), POST /chat/messages.
- twitch/mock.ts: MockChatSource (accepts messages pushed from the feeder over a local HTTP endpoint POST /mock/chat or in-process) and MockHelix that logs marker/clip/chat calls to console and to logs/mock-helix.log and returns fake ids/urls.
- hype/detector.ts: HypeDetector with rolling baseline (e.g. EWMA of per-second score over ~60s windows) scoring message rate, emote density, and keyword hits (W, POG, POGGERS, LOL, LMAO, omo, ehen, haha, KEKW, gg, clip it, ...; case-insensitive, whole-word). Spike when score > baseline * multiplier and above an absolute floor, with cooldown. Pure and deterministic given timestamps (inject clock) so it is testable.
- hype/clipper.ts: on spike -> HelixClient.createMarker + createClip + poll getClip; record a Moment {id, ts, score, peakMessages(sample), markerId, clipId, clipUrl, status}; keep top N moments by score; emit events.
- translate/: Translator with provider chain + language routing. detect.ts: lightweight language detection (heuristics + small word lists for pidgin/yoruba (incl. diacritics like ẹ ọ ṣ and tone marks)/french/spanish/english; return {lang, confidence}). providers: PidginPhraseProvider (phrase-list based pidgin->english and english->pidgin, with a decent phrase list ~60 entries, e.g. "how far"->"how are you", "wetin dey happen"->"what is happening", "omo"->"wow", "e choke"->"it's amazing", "abeg"->"please", "I no fit"->"I can't", "na wa"->"wow/unbelievable", "wahala"->"trouble"...), LibreTranslateProvider (HTTP POST {LIBRETRANSLATE_URL}/translate; disabled if URL unset), NllbProvider stub implementing the interface for Yoruba (returns not-configured unless NLLB_URL set; documented request shape), OpenAIProvider OFF by default (only active if OPENAI_ENABLED=true and key). Also a tiny built-in YorubaGlossaryProvider (common greetings/phrases) as offline fallback with low confidence. Router picks providers per source language, falls back down the chain, returns {original, lang, translated, provider, confidence}. English messages are not translated. Streamer command `!reply <lang> <text>` (from the broadcaster only) translates english -> target and sends via HelixClient.sendChatMessage.
- game/vote.ts: VoteGame: QuietDetector triggers a vote when chat rate stays below a threshold for N seconds (and no game in last cooldown); picks a prompt from a list (e.g. "Next challenge? a) no-scope run b) speedrun c) viewer picks"), accepts `!vote a|b|c` one vote per user (last vote wins), runs for duration, tallies and announces winner via sendChatMessage. Deterministic tally function exported for tests.
- server.ts: express app serving /overlay (public/overlay/index.html), /overlay/* assets, GET /events (SSE) broadcasting state events: moment:new/update, hype:score (throttled ~2/s), translation:new, vote:start/update/end, plus GET /state snapshot. POST /mock/chat in mock mode.
- index.ts: wires everything based on MODE.
